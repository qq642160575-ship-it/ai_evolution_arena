
# 📝 完整 PRD 与架构设计：AI 进化竞技场 (AI Evolution Arena)



## 一、 产品定位与核心理念

* **产品形态：** ToC、免登录、即开即用的 AI 大模型盲测与评测网站。

* **核心玩法：** 每个会话（Session）固定随机抽取两款匿名模型。用户进行 3 轮对话并强制二选一评价，在第 3 轮评价后触发“开盲盒”揭晓模型真身。

* **北极星指标：** 收集高质量、排除“回复速度”与“排版格式”干扰的纯粹人类偏好数据（Human Evaluation）。



---



## 二、 核心功能模块 (MVP 范围)



### 1. 盲测对战区 (Battle Arena)

* **全局防干扰引导：** 页面顶部常驻提示：“⚖️ *评审原则：请忽略回复速度与排版格式，仅针对回答内容的逻辑、准确性及有用性进行评价。*”

* **对话展示 (Side-by-Side)：** * 左右或上下双栏展示，两栏使用完全一致的 Markdown 渲染样式。

  * 采用打字机效果（SSE 流式输出），双模型同时输出。

* **强制评价机制 (Voting)：**

  * 在双方模型均输出完毕前，输入框及评价按钮处于 `disabled` 状态。

  * 4 个评价维度：`👈 左侧更优` | `🤝 两者双优` | `👎 两者双差` | `右侧更优 👉`。

* **状态轮转与揭晓 (The Reveal)：**

  * **第 1、2 轮：** 评价后解锁输入框，进入下一轮。模型保持“模型 A / 模型 B”的匿名状态。

  * **第 3 轮（终局）：** 评价完成后，触发翻转或高亮动效，**瞬间揭晓两款模型的真实名称**。输入框隐藏，展示“📊 查看排行榜”与“🔄 开启新对决”按钮。



### 2. 研究报告页 (Evolution Hub)

* **实时战力榜 (Leaderboard)：** 基于全站历史数据，展示各模型的综合胜率（如 Elo 积分或简单胜率百分比）。

* **透明度声明：** 告知用户本站数据来源及防刷票机制，增强平台科研公信力。

## 三、 系统架构与技术栈选型



采用**前后端分离**架构，结合 LangChain 实现底层模型的标准化接入。



| 层级 | 技术栈 | 核心职责 |

| :--- | :--- | :--- |

| **前端 (Client)** | React / Vue 3 + Tailwind CSS | 渲染 UI、维护 3 轮对话状态机、接收双路 SSE 流并实现并排打字机效果。 |

| **后端 (API)** | Django + Django Ninja (或 DRF) | 处理 HTTP 请求、管理 Session 状态、记录评价数据、提供 REST 接口与 SSE 流。 |

| **大模型编排层** | **LangChain (Python)** | 统一封装各家大模型 API，管理对话历史，执行并发异步流 (`astream` + `asyncio`)。 |

| **数据库 (DB)** | SQLite (Demo) -> PostgreSQL | 存储 `BattleSession` (对局信息) 和 `EvaluationRecord` (投票记录)。 |







---



## 四、 核心业务流程与 API 契约



整个应用的生命周期由前端状态机与 4 个核心 API 驱动：



### 1. 初始化对决 (Start Session)

* **触发时机：** 用户首次进入主页或点击“开启新对决”。

* **后端动作：** 生成 `session_id`，基于动态平衡权重，从模型池中随机绑定模型 A 和模型 B，存入数据库。

* **API:** `POST /api/battle/start/` -> 返回 `session_id` 和当前轮次 `0`。



### 2. 发送对话与双流接收 (Chat & Stream)

* **触发时机：** 用户提交 Prompt。

* **后端动作 (LangChain 核心)：**

  1. 接收 `session_id` 与 Prompt。

  2. 从数据库查出绑定的两款模型，利用 LangChain 实例化对象（如 `ChatOpenAI`, `ChatTongyi`）。

  3. 使用 Python `asyncio.gather` 并发调用两个模型的 `astream` 方法。

  4. 将生成的 Chunk 打上标签 (`{"model": "A", "chunk": "..."}`)，通过 **Server-Sent Events (SSE)** 推送给前端。

* **API:** `POST /api/battle/chat/` -> 返回 SSE 数据流。



### 3. 提交评价与揭晓身份 (Vote & Reveal)

* **触发时机：** 用户点击 4 个评价按钮之一。

* **后端动作：** 记录本轮投票数据。判断当前轮次，如果不足 3 轮，返回继续；如果是第 3 轮，返回模型真实名称。

* **API:** `POST /api/battle/vote/`

  * 前两轮返回：`{"is_completed": false, "current_turn": 1}`

  * 第三轮返回：`{"is_completed": true, "reveal": {"left": "gpt-4o", "right": "claude-3.5"}}`



### 4. 获取排行榜 (Leaderboard)

* **触发时机：** 用户进入 Evolution Tab 页。

* **后端动作：** 聚合查询全站投票数据，计算胜率。

* **API:** `GET /api/report/leaderboard/`

## 五、 后续扩展预留 (Future Proofing)

1. **LangGraph 升级：** 预留了 LangChain 生态。未来可以轻松将 `POST /api/battle/chat/` 的逻辑重构为一个 LangGraph 的状态图，加入“AI 裁判自动打分”节点作为与人类投票的对比对照组。

2. **防作弊机制：** 后端可在 Session 生成时绑定前端指纹（Fingerprint）或 IP 频率限制，确保刷票数据不污染排行榜。
