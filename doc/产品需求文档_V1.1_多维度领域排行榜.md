# 产品需求文档 (PRD): AI Evolution Arena - 多维度领域排行榜 V1.1

**文档状态:** 定稿 | **产品经理:** [你的名字] | **最后更新:** 2026-03-30
**核心技术选型更新:** 后台意图分类器指定使用 `Qwen/Qwen2.5-7B-Instruct`。

## 1. 项目背景与目标 (Background & Objectives)
当前 (V1.0 MVP 阶段) 仅有基于综合数据的全局排行榜，无法细化衡量模型在特定领域的表现。本期（V1.1）将通过细化特定领域（Domain）排行榜提升评测数据的维度和科研价值，同时继续坚守“免登录、即开即用”的极简零前置体验原则。

## 2. 核心功能范围 (Scope)
本期将支持以下 5 大核心领域的细分排行：
1.  💻 代码与开发 (coding)
2.  🧠 逻辑与数学 (logic)
3.  ✍️ 文本创作与翻译 (creative)
4.  🎯 指令遵循 (instruction)
5.  💬 日常问答 (general)

## 3. 用户故事 (User Stories)
* **作为极客/开发者**，我希望能查看“代码与开发”专属的榜单，帮助我在日常 Coding 中更好地挑选高战力模型。
* **对于普通盲测用户**，我希望在使用系统时始终不被打断，享受顺畅的盲测与判决体验，同时我提出的极客问题能通过系统的无感分类助力特定领域榜单的数据化积累。

## 4. 功能需求详细说明 (Functional Requirements)

### 4.1 核心机制：基于 Qwen2.5-7B 的 Prompt 自动路由分类
为了保持前端极简（用户侧0参与分类），核心逻辑依靠**后端异步判别**策略实现。

* **指定分类引擎:** 采用 `Qwen/Qwen2.5-7B-Instruct` 作为专用的意图分类器。（**部署建议**：初期可由于成本控制直接调用 SiliconFlow 等 API 平台，后期若并发极高可低成本本地化并使用 vLLM 部署以追求极致速度吞吐）。
* **业务逻辑:**
    1.  当对局刚建立时，用户通过 `POST /api/battle/chat/` 进行首轮提问 (`Prompt`)。
    2.  FastAPI 后端的 `BattleService` 在调用 LangChain 层流式向前端双路推送响应内容的**同时**，通过异步任务（`asyncio.create_task`）非阻塞单次调用 Qwen2.5-7B 接口。
    3.  Qwen 的分类器根据系统限定的 System Prompt，要求被严格约束输出 5 个枚举标签之一。
    4.  异步任务得出分类结果后，更新 `domain_category` 至对应的 `BattleSession` 记录中。
* **边界与异常处理:**
    * **容错兜底:** 若 Qwen 接口发生超时（设定极短超时阈值如 2 秒）、报错或返回任何非枚举范围的脏数据流窜，系统立刻回退将其归类为 `general`。任何异常情况均**绝不阻塞**主流程响应。
    * **继承与降本:** 意图分类仅针对单个 `BattleSession` 对局当中的“第一轮 Prompt”（且仅执行一次），之后轮次（如第2轮、第3轮）的对话将会自动继承第一轮设定的领域标签，避免重复调用的算力冗余消耗。

### 4.2 前端展现：排行榜模块重构 (Leaderboard UI)
* **UI 布局:** 在 `Evolution Hub` 排行榜页面上方区域，增加一组无感切换的次级 Tab 栏（或药丸状 Toggle）：“🏆 综合排行”、“💻 代码”、“🧠 逻辑”、“✍️ 创作”、“🎯 指令”、“💬 问答”。
* **交互表现:** 用户切换 Tab 时将触发并发送形如 `GET /api/report/leaderboard/?category=xxx` 的请求，动态拉取基于 `domain_category` 过滤后的最新排名，并确保卡片切换带有平滑过渡动效。

## 5. 技术实现与架构说明 (Technical & Architecture Specs)

### 5.1 数据库结构变更 (Database Schema)
在 `backend/models.py` 的对局模型 `BattleSession` 中新增领域分类标签字段，记录具体的英文枚举值，以作为后期排序和报表统计维度：

```python
class BattleSession(Base):
    __tablename__ = "battle_sessions"
    # ... 现有字段如 id, model_a, model_b ...
    
    # 新增：领域标签字段 (coding, logic, creative, instruction, general)
    domain_category = Column(String, default="general", index=True) 
```

### 5.2 API 接口变更 (API Updates)
* **Endpoint:** `GET /api/report/leaderboard/`
* **变更点:** 入参新增可选的 Query 参数 `category: Optional[str] = None`。后端的 `BattleService.get_leaderboard()` 将首先检查该参数，若存在则在 SQLAlchemy 查询中添加对应的 `.filter(models.BattleSession.domain_category == category)` 的筛选条件，再基于子集完成 Elo 分数或百分比胜率的统算。

### 5.3 LangChain 编排层：异步意图分类器实现
在 `backend/llm.py` 中，针对指定的大模型建立一个轻耦合但高容错率的函数 / Chain 用途专门完成分类。

* **模型参数设置 (Hyperparameters):**
    * `temperature = 0.0` (绝对固定为 0，防止发散并确保分类落入设定范畴)
    * `max_tokens = 5` (极严限制，一旦吐出标签目标词即被截断，防止废话解释，显著降低网络延迟)
* **System Prompt 规范:**
    为保证强指令遵循能力，请严格采用以下模板格式给 Qwen 送入参数：

> **System Message:**
> 你是一个极其高效的意图分类路由。请将用户的输入严格分类到以下 5 个枚举值之一：`coding`, `logic`, `creative`, `instruction`, `general`。
> 
> 规则：
> 1. 只允许输出这 5 个英文单词中的一个。
> 2. 绝对不能输出任何解释、标点符号、换行符或多余字符。
> 3. 如果无法判断，默认输出 `general`。
> 
> **Human Message:**
> {user_input}
