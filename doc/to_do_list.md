# 📝 AI 进化竞技场 (AI Evolution Arena) - 任务规划 (To-Do List)

根据《项目概述.md》，将项目从零到一拆解为以下开发步骤，后续可依此逐步实现：

## 阶段一：项目初始化与基础设施搭建
- [ ] 1.1 **仓库初始化**：创建 Django / FastAPI 后端项目基础结构，配置虚拟环境。
- [ ] 1.2 **前端初始化**：创建 React / Vue 3 项目，配置 Tailwind CSS 和基础路由。
- [ ] 1.3 **数据库建模**：设计并创建 `BattleSession` (对局信息) 和 `EvaluationRecord` (投票记录) 的数据库模型。
- [ ] 1.4 **大模型接入层**：集成 LangChain，封装基类，配置至少两款大模型（如 OpenAI、阿里云通义千问等）的 API Key 和调用逻辑，确保支持异步并发流式输出 (`astream`)。

## 阶段二：核心对战 API 开发 (后端)
- [ ] 2.1 **初始化对决 API (`POST /api/battle/start/`)**：实现 Session 生成、双模型随机绑定及持久化记录。
- [ ] 2.2 **流式对话 API (`POST /api/battle/chat/`)**：
    - [ ] 接收 Prompt。
    - [ ] 利用 LangChain 并发调用绑定的两款模型。
    - [ ] 构建 Server-Sent Events (SSE) 服务，将双路 Token 推送给前端。
- [ ] 2.3 **评价与揭晓 API (`POST /api/battle/vote/`)**：
    - [ ] 记录每一轮的四个维度投票（左优、双优、双差、右优）。
    - [ ] 控制 3 轮的回合状态机。
    - [ ] 第 3 轮投完票后，返回两款模型的真实名称。

## 阶段三：对战区主体验开发 (前端)
- [ ] 3.1 **主对战 UI 布局**：
    - [ ] 顶部防干扰引导提示。
    - [ ] 左右或上下双栏对话展示区（支持 Markdown 渲染一致性）。
    - [ ] 底部输入框和强制评价按钮组。
- [ ] 3.2 **状态机与流式接收**：
    - [ ] 接收后端 SSE 数据流，实现双线同时输出的打字机效果。
    - [ ] 在双方模型均输出完毕前，输入框及评价按钮处于 `disabled` 状态。
- [ ] 3.3 **轮次控制与揭晓 (The Reveal) 动效**：
    - [ ] 维护 3 轮对话状态。
    - [ ] 第 3 轮评价完成后，触发翻转或高亮动效，瞬间揭晓两款模型的名称。
- [ ] 3.4 **揭晓后状态**：隐藏输入框，展示“查看排行榜”和“开启新对决”按钮。

## 阶段四：排行榜与数据报表 (Evolution Hub)
- [ ] 4.1 **排行榜 API (`GET /api/report/leaderboard/`)**：聚合查询全站数据，计算各模型的胜率或评分。
- [ ] 4.2 **前端排行榜页展示**：实现实时战力榜的数据可视化展示。
- [ ] 4.3 **透明度声明模块**：说明数据来源及防刷票机制，增强公信力。

## 阶段五：系统联调、测试与优化
- [ ] 5.1 **全链路联调**：走通完整的“初始化 -> 3轮对话 -> 揭晓 -> 排行榜更新”闭环。
- [ ] 5.2 **防作弊机制开发 (可选/预报)**：增加前端指纹识别或 IP 频率限制。
- [ ] 5.3 **LangGraph 升级预演 (可选)**：尝试将对话处理逻辑重构为 LangGraph 节点图。
- [ ] 5.4 **部署与上线**：配置 Dockerfile 及部署脚本。
