## 1. 项目概述 (Project Overview)
### 1.1 项目背景
本项目旨在搭建一个大模型进化竞技场（AI Evolution Arena），通过匿名、随机的双模型对决机制，由用户进行多轮对话评估，从而生成客观的大模型能力排行榜。

### 1.2 核心目标
- **多模型评测**：支持接入多种主流大模型（GPT, 通义千问等）。
- **盲测机制**：对决过程中隐藏模型名称，确保评价的公平性。
- **流式体验**：实现双路并发的流式（SSE）对话输出。
- **战力排行**：基于用户投票数据，计算模型胜率及排名。

## 2. 核心功能模块 (Core Functional Modules)

### 2.1 Backend (后端)
- **Battle Service (`backend/services.py`)**: 
    - `start_battle`: 随机选择两个模型并初始化会话。
    - `generate_chat_stream`: 使用 `asyncio.Queue` 和 `EventSourceResponse` 实现异步双模型并发流式输出。
    - `vote_round`: 记录用户每一轮的投票（left/right/both_good/both_bad），维护 3 轮状态机。
    - `get_leaderboard`: 聚合投票数据并计算胜率。
- **Database Model (`backend/models.py`)**: 
    - `BattleSession`: 记录 `model_a`, `model_b`, `is_completed`, `history` (JSON 格式)。
    - `EvaluationRecord`: 精确记录每一轮的 `prompt`, `response_a`, `response_b` 及投票结果。
- **LLM Integration (`backend/llm.py`)**: 封装各模型的 API 调用逻辑。

### 2.2 Frontend (前端)
- **Arena UI (`frontend/src/App.tsx`)**: 
    - 对战主界面，负责处理 SSE 流式接收和打字机效果展示。
    - 维护 3 轮对话的状态机逻辑。
- **Leaderboard (`frontend/src/components/Leaderboard.tsx`)**: 
    - 异步获取并展示模型胜率排行榜。
- **Environment Config**:
    - `frontend/.env`: 配置 `VITE_API_BASE_URL` 指向后端。

## 3. 技术架构与环境 (Technical Architecture & Environment)

### 3.1 技术栈
- **后端**: Python 3.10+, FastAPI, SQLAlchemy (Async), SQLite, Pydantic, sse-starlette
- **前端**: Node 18+, Vite, React, TypeScript, Tailwind CSS
- **接口**: RESTful API + SSE (Server-Sent Events)

### 3.2 数据库设计
- 使用 SQLite 存储，文件路径为 `backend/arena.db`。
- 核心表：`battle_sessions` (主会话), `evaluation_records` (明细投票记录)。

### 3.3 环境配置
- **后端启动**: `pip install -r requirements.txt && uvicorn main:app --reload` (在 `backend` 目录下)。
- **前端启动**: `npm install && npm run dev` (在 `frontend` 目录下)。
- **关键环境变量**:
    - `backend/.env`: 需配置 `OPENAI_API_KEY`, `DASHSCOPE_API_KEY` 等。

## 4. 关键流程说明 (Key Workflows)

### 4.1 模型对比流程
1. 前端 `App.tsx` 调用 `POST /api/battle/start/` 获取 `session_id`。
2. 用户输入 Prompt，前端发起 `POST /api/battle/chat/` SSE 连接。
3. 后端 `BattleService` 并发调用两个模型，将 Token 实时推送至前端。
4. 用户评价后调用 `POST /api/battle/vote/`。
5. 第 3 轮投票结束后，后端返回 `is_completed=True` 及模型真实名称，前端展示揭晓动效。

### 4.2 排行榜计算
- 目前基于 `evaluation_records` 中的 `vote_result` 进行简单胜率统计 (`wins / total_matches`)。未来可升级为 Elo 评级系统。
